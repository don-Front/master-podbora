# Проблемы распознавания ОЛ — для доработки пайплайна

**Источник:** `\\192.168.1.198\...\Для доклада` — 62 файла (PDF/DOCX), прогон 13.07.2026  
**Методика:** AI-эталон (аудит-промпт) vs production `run_pdf_order_pipeline`  
**Сводка:** средняя точность **84.6%**, медиана **100%** (40 файлов без расхождений)

> Эталон — тоже LLM, не ручная разметка. При расхождении смотреть OCR в `results/*.json`.

---

## P0 — критичные паттерны (часто / сильно влияют на подбор)

### 1. Расход `flowMin` / `flowMax` — 13 ошибок
**Симптом:** бот берёт число из соседней строки таблицы или путает min/max.

| Файл | Проблема |
|------|----------|
| `6120.001.П.0_0.0001-МЕО.УИРГ.ОЛ.PDF` | flowMax 40000 вместо 3; pressure 1.2 МПа вместо 100 кПа; DN 300 вместо 50 |
| `Опросники\TFG\Опросный лист (5).pdf` | flowMax 12593 вместо 12 (масштаб/единицы) |
| `Опросники\TFG\Опросный лист (6).pdf` | аналогично (5) |
| `Опросники\UFG\Z958957_ОЛ.pdf` | расходы не извлечены (0.01–0.5) |
| `ОЛ_1.pdf` | flowMax 35000 vs эталон 5500 — **проверить OCR**: в тексте «от 5500 … до 35000» |

**Доработка:** усилить `_prefer_consistent_heuristic_ranges`, парсить пары «от … до …» до LLM, валидировать flowMax > flowMin.

### 2. Точность `accuracy` — 9 ошибок значения
**Симптом:** «0,5» vs «0.5%», класс «А» vs «1%», диапазон «0.5%-0.3%».

| Файл | эталон | бот |
|------|--------|-----|
| `тендер.PDF` | 0,5 | 0.5% |
| `Z958957_ОЛ.pdf` | 0.5%-0.3% | 1% |
| `Опросный лист (5).pdf` | расхождение класса/процента |

**Доработка:** нормализация `normalize_accuracy_value` — принимать голые числа как проценты только при явной метке «%» или «класс».

### 3. Единицы `temperature_unit` / `flow_unit` / `pressure_unit` — 18+ расхождений
**Симптом:** бот подставляет дефолты (°C, МПа, ст.м³/ч), когда в ОЛ другие единицы; или путает поле с числом (`pressureMax='МПа'`).

| Файл | Проблема |
|------|----------|
| `6120.001...ОЛ.PDF` | кПа → МПа, м³/ч → ст.м³/ч |
| `doc137366...pdf` | бот заполнил pressure_unit/temperature_unit, эталон — null |

**Доработка:** извлекать единицы regex из строки рядом с числом; не подставлять дефолт, если в документе явно другая единица.

### 4. Тип газа `gas_type` — 8 проблем
**Симптом:** обобщение до «природный газ» вместо ГОСТ/состава; путаница medium vs состав.

| Файл | Проблема |
|------|----------|
| `Z958957_ОЛ.pdf` | medium='CH4' (бот) — **баг**: medium должен быть gas, состав в gas_type |
| `тендер.PDF` | «природный (ГОСТ 5542-2014)» → «природный газ» |
| `ОЛ_1.pdf` | эталон «пропан-бутан», бот «природный газ» — **в OCR явно «Природный газ»**, эталон ошибся |

**Доработка:** запретить non-enum в `medium`; для состава — брать строку «компонентный состав» целиком.

### 5. Диаметр `diameter` — 4 ошибки значения
| Файл | эталон | бот |
|------|--------|-----|
| `тендер.PDF` | 100 | 10 (потеря нуля / OCR) |
| `6120.001...ОЛ.PDF` | 50 | 300 |

**Доработка:** приоритет DN/Ду из шапки; OCR-постобработка «DN 100» vs «DN 10».

## P1 — средний приоритет

### 6. Дублирование `duplication_type` — 3 пропуска бота
| Файл | эталон | бот |
|------|--------|-----|
| `ОЛ 11448 ANSI600.pdf` | partial | null |
| `doc137366...pdf` | partial | none |
| `doc161193...pdf` | full | null |

**Доработка:** `extract_duplication_type_from_text` — расширить шаблоны CFM/UFL («частичное/полное резервирование»).

### 7. Температуры среды vs окружающей — путаница min/max
| Файл | Проблема |
|------|----------|
| `ОЛ_1.pdf` | бот: tempMedium -35..39, эталон: tempAmbient -35..39 (в OCR блок «температура воздуха») |
| `тендер.PDF` | tempAmbientMin -20 vs -40 |

**Доработка:** разделять блоки «температура на входе» / «температура воздуха» / «климатические условия».

### 8. LLM возвращает пустой JSON
**Лог:** `LM Studio извлечение не удалось: LLM вернула пустой JSON-объект` — часто на CFM ANSI600, но эвристики спасают (100% совпадение с эталоном).

**Доработка:** retry с temperature=0; fallback только на эвристики с флагом «низкая уверенность».

3. Улучшить маршрутизацию температур (среда vs воздух).
4. Расширить `duplication_type` для CFM/UFL.
5. Добавить детектор «не опросный лист» для docx-списков.
6. Прогнать регрессию: `py -3 tests/run_doklad_ol_audit.py --force` на 15 худших файлах.
