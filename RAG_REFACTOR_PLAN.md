## Этап 1: Исправление критических RAG-багов (приоритет: высокий)

### Задача 1.1: Исправить формулу score в VectorStore.search
- **Файл**: `back/chatbot/api/chatbot_core/vector_store.py`
- **Суть**: Сейчас используется `confidence = 1 - dist/2`, но при `IndexFlatIP` и нормализованных эмбеддингах `dist` — это косинусное сходство (от -1 до 1). Правильная формула: `score = float(dist)`, где чем выше, тем лучше.
- **Действие**:
  - Переименуй `distances` → `similarities`.
  - Удали `confidence = 1 - dist/2`.
  - Используй `score = float(similarity)`.
  - Обнови пороги: старый `threshold` 0.75 становится 0.75 (но теперь это косинус). Проверь в `adjust_search_parameters` и `config.yaml`.
- **Проверка**: Напиши тест, который сравнивает результаты поиска для двух похожих запросов — более релевантный должен иметь более высокий score.

### Задача 1.2: Увеличить `top_k` по умолчанию
- **Файл**: `back/project/config.yaml`
- **Суть**: сейчас `top_k: 1` — этого катастрофически мало.
- **Действие**: измени на `top_k: 8`.
- **Дополнительно**: в `chatbot.py` в `adjust_search_parameters` для типа `attribute` оставь 25, для `description` — 15, для остальных — не ниже 5.

### Задача 1.3: Исправить логику фильтрации по `chunk_types_filter`
- **Файл**: `back/chatbot/api/chatbot_core/chatbot.py` (метод `generate_response`)
- **Проблема**: после `smart_search` происходит фильтрация по типам чанков, но она отбрасывает чанки с нужной информацией, если тип не совпадает.
- **Действие**:
  - Если после фильтрации осталось < 2 чанков, отключи фильтр и повтори поиск (сделай fallback).
  - Логируй такой случай.

### Задача 1.4: Добавить принудительное цитирование источников в ответе
- **Файл**: `back/chatbot/api/chatbot_core/llm_client.py`
- **Суть**: Требование FR-11 — бот должен указывать название документа и номер пункта/страницы.
- **Действие**:
  - Измени `build_context(chunks)`: для каждого чанка добавь метаданные `document_name`, `page` или `paragraph` (если есть).
  - В системный промпт добавь строгое правило: *«В конце каждого утверждения, взятого из документа, поставь ссылку в формате [Документ: Название, стр. X]».*
  - Если источник неизвестен (старый чанк), бот должен написать «(источник не указан)».

### Задача 1.5: Отключить искусственный бустинг ProductDetector
- **Файл**: `back/chatbot/api/chatbot_core/product_detector.py`
- **Проблема**: `search_chunks_by_product` присваивает score 0.8 или 0.9, что доминирует над реальной релевантностью.
- **Действие**:
  - Удали жёсткую установку score. Вместо этого для product-чанков используй тот же метод расчёта сходства (embedding similarity) между вопросом и текстом чанка.
  - Либо просто добавь эти чанки в результаты без изменения score, а при сортировке пусть будет естественный порядок.

## Критерии готовности проекта

- **FR-11/AC-04**: В ответах на нормативные вопросы обязательно указание ГОСТ/документа, пункт/страница.
- **AC-02**: Сценарий формального подбора оборудования работает для 10 типовых сценариев.
- **AC-03**: Свободный текст извлекает параметры и задаёт уточнения.
- **AC-08**: При отсутствии источника бот сообщает «не могу подтвердить» и предлагает эскалацию.
- **Метрики**: CSAT > 85%, TTR < 30 секунд (на реальном оборудовании).
- **Код**: все сервисы выделены, типизированы, покрыты тестами на 70% ключевых путей.

## Что делать, если что-то пошло не так?

- Если LM Studio недоступна — используй заглушку, которая возвращает «Сервис временно недоступен» и логирует ошибку.
